How an Automation Runs - Step by Step

SCENARIO: New lead is created in your CRM ═══════════════════════════════════════════ STEP 1: TRIGGER FIRES ├─ Lead created event detected ├─ Lead data captured: {id, name, score, source, company, email} └─ System queries for automations with "Lead Created" trigger STEP 2: FIND MATCHING AUTOMATIONS ├─ Find all ENABLED automations for this company ├─ Filter by trigger type = "Lead Created" └─ Found: 2 automations ├─ "Route high-quality leads" └─ "Send welcome email" STEP 3: EXECUTE FIRST AUTOMATION ├─ Automation ID: auto_12345 ├─ Create AutomationExecution record (status: running) ├─ Load all nodes for this automation └─ Load all edges (connections) STEP 4: START FROM FIRST NODE ├─ Node: "Lead Created" (trigger) ├─ Status: confirmed ✓ └─ Move to next connected node STEP 5: PROCESS ACTION NODE ├─ Node: "Update Field" ├─ Config: {field: "status", value: "new_lead"} ├─ Execute: Update lead.status = "new_lead" ├─ Log result: {status: "completed", timestamp: now} └─ Move to next node STEP 6: PROCESS CONDITION NODE ├─ Node: "Condition: Score > 50?" ├─ Evaluate: Is lead.score (72) > 50? ├─ Result: YES ✓ └─ Branch to YES path → "Assign to Sales Exec" STEP 7: EXECUTE ACTION NODE (Assign) ├─ Node: "Assign to Sales Exec" ├─ Config: {method: "round-robin", filter: "active_users"} ├─ Get next user in rotation: Alex (sales_exec_001) ├─ Execute: Assign lead to Alex ├─ Create AutomationExecutionLog: {action: "assign", assigned_to: "Alex"} └─ Move to next node STEP 8: EXECUTE ACTION NODE (Send Email) ├─ Node: "Send Email" ├─ Config: {template_id: "welcome_email", recipient: lead.email} ├─ Load template: "Welcome to our platform!" ├─ Send email to lead@company.com ├─ Log result: {email_sent: true, message_id: "msg_789"} └─ Move to next node STEP 9: PROCESS UTILITY NODE (Delay) ├─ Node: "Delay" ├─ Config: {duration: 5, unit: "days"} ├─ Schedule resume in 5 days ├─ Pause execution (wait in queue) └─ When 5 days passed → Resume at next node STEP 10: COMPLETE AUTOMATION ├─ Automation finished all nodes ├─ Mark AutomationExecution as "completed" ├─ Record final timestamp └─ Store complete result: ├─ Trigger: Lead created (id: lead_999) ├─ Actions: 4 executed successfully ├─ Status assignments: 1 (Alex) ├─ Emails sent: 1 ├─ Duration: 0.5 seconds (+ 5 day delay) └─ Result: SUCCESS ✓ STEP 11: POST-EXECUTION ├─ Update dashboard metrics ├─ Archive execution log ├─ Alert admins if any errors └─ Ready for next automation run

Automation Node Types

🔴 TRIGGERS (Start Point)

  • Lead Created
  • Lead Score Changed
  • Deal Moved to Stage
  • Contact Updated
  • Ticket Created
  • Scheduled (Time-based)
  • Manual (Admin Click)

🟢 ACTIONS (Do Something)

  • Assign Lead/Deal
  • Send Email
  • Send SMS
  • Create Task
  • Update Field
  • Change Status
  • Create Deal
  • Notify Team

🟡 CONDITIONS (Decision)

  • Score Check (> < =)
  • Source Match
  • Field Equals
  • Score Range
  • If/Then/Else

🔵 UTILITIES (Advanced)

  • Delay (Wait X days)
  • Wait for Event
  • Branch (Parallel)
  • Merge
  • Loop

Database Schema - 5 New Tables

Table 1: Automation

id (PRIMARY KEY)
companyId (Foreign Key) - Multi-tenant
name - Display name
description - What it does
enabled - Boolean (active/inactive)
createdBy - Admin who created it
createdAt, updatedAt - Timestamps
Table 2: AutomationNode

id (PRIMARY KEY)
automationId (Foreign Key)
type - "trigger", "action", "condition", "delay", "branch"
label - Display name
position - {x: 100, y: 50} for canvas
config - JSON with node-specific settings
Table 3: AutomationEdge

id (PRIMARY KEY)
automationId (Foreign Key)
fromNodeId (Foreign Key)
toNodeId (Foreign Key)
label - "yes", "no", "success", "error"
Table 4: AutomationExecution

id (PRIMARY KEY)
automationId (Foreign Key)
triggeredBy - "lead_id", "deal_id", "manual"
triggeredValue - Actual ID (e.g., "lead_12345")
status - "running", "completed", "failed", "paused"
startedAt, completedAt - Timestamps
result - JSON with execution results
Table 5: AutomationExecutionLog

id (PRIMARY KEY)
executionId (Foreign Key)
nodeId (Foreign Key)
status - "completed", "failed", "skipped"
input - What data went in
output - What came out
executedAt - When it ran
errorMessage - If it failed
